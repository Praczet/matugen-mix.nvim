# matugen-mix.nvim

A tiny Neovim helper for making an existing colorscheme slightly harmonize with a
`matugen` palette.

It does not replace your colorscheme.  
It does not generate a full theme.  
It does not try to become a universal design system, because that is how small
weekend ideas become architectural paperwork.

It simply takes colors from `matugen`, mixes them gently into selected
colorscheme colors, and lets Neovim look a little less like it was excluded from
the rest of the desktop.

## Why

My desktop theme is generated from the current wallpaper using `matugen`.

That means the wallpaper influences things like:

- Hyprland
- Waybar
- Rofi
- terminal colors
- possibly other infected parts of the environment

Neovim, however, usually uses a fixed colorscheme. In my case that is mostly
`tokyonight-moon`.

The problem is not that TokyoNight is ugly. It is not. We are not monsters.

The problem is that a fixed Neovim background can appear dull, flat, or slightly
disconnected when it sits next to a wallpaper-derived desktop palette.

This is mostly a perception issue: colors change their apparent character
depending on nearby colors. A background that looks good alone can look
desaturated or dead when placed against a glowing blue/pink/purple wallpaper.

So the idea is:

```text
keep the original colorscheme identity
+
borrow a very small amount of matugen mood
=
less visual disagreement
```

In other words:

```text
TokyoNight Moon, but it knows what wallpaper it lives with.
```

## What it does

`matugen-mix.nvim` reads a generated Lua palette file, for example:

```text
~/.config/nvim/lua/generated/matugen-colors.lua
```

Then it mixes selected colorscheme values with selected `matugen` colors.

For example:

```text
TokyoNight bg + 5% matugen primary = slightly warmer/lifted bg
```

This is meant to be subtle.  
If it screams, it is wrong.  
If it quietly stops annoying you, it is working.

## What it does not do

This plugin does not:

- replace your colorscheme
- generate a complete Neovim theme
- manage wallpapers
- run `matugen`
- configure Hyprland, Waybar, Rofi, or your tea kettle
- promise taste, because computers are already bold enough

It only mixes colors.

## Matugen setup

First, create a template for Neovim colors.

Example path:

```text
~/.config/matugen/templates/nvim-colors.lua
```

Template:

```lua
-- Generated by matugen.
-- Do not edit by hand unless you enjoy losing small wars against automation.

return {
  source = {
    image = "{{ image }}",
  },

  colors = {
    background = "{{ colors.background.default.hex }}",
    surface = "{{ colors.surface.default.hex }}",
    surface_variant = "{{ colors.surface_variant.default.hex }}",

    primary = "{{ colors.primary.default.hex }}",
    secondary = "{{ colors.secondary.default.hex }}",
    tertiary = "{{ colors.tertiary.default.hex }}",

    on_background = "{{ colors.on_background.default.hex }}",
    on_surface = "{{ colors.on_surface.default.hex }}",

    error = "{{ colors.error.default.hex }}",
  },
}
```

Then add the template to `matugen`.

Example:

```toml
[templates.nvim]
input_path = "~/.config/matugen/templates/nvim-colors.lua"
output_path = "~/.config/nvim/lua/generated/matugen-colors.lua"
```

After running `matugen`, Neovim should have a generated module like this:

```lua
return {
  source = {
    image = "~/.config/backgrounds/woman_reading_pinker.png",
  },

  colors = {
    background = "#161217",
    surface = "#161217",
    surface_variant = "#4c444c",

    primary = "#e6b6f1",
    secondary = "#d5c0d7",
    tertiary = "#f5b7b3",

    on_background = "#eae0e7",
    on_surface = "#eae0e7",

    error = "#ffb4ab",
  },
}
```

Test inside Neovim:

```vim
:lua print(vim.inspect(require("generated.matugen-colors")))
```

If that prints a table, the infection route is open.

## Usage with TokyoNight

Example TokyoNight configuration:

```lua
return {
  {
    "folke/tokyonight.nvim",

    dependencies = {
      {
        dir = "~/Development/lua/NeoVim/matugen-mix.nvim",
        name = "matugen-mix.nvim",
      },
    },

    opts = function(_, opts)
      opts = opts or {}

      local matugen_mix = require("matugen-mix")

      matugen_mix.setup({
        enabled = true,

        colors_module = "generated.matugen-colors",

        palette = {
          bg = 0.05,
          bg_dark = 0.04,
          bg_float = 0.06,
          bg_sidebar = 0.06,
        },
      })

      opts.style = "moon"

      opts.on_colors = function(colors)
        matugen_mix.apply_tokyonight(colors, {
          accent = "primary",
        })
      end

      opts.on_highlights = function(h, c)
        h.WinSeparator = { fg = c.blue7, bg = "NONE" }
        h.VertSplit = { link = "WinSeparator" }

        -- Your other highlight tweaks can live here.
        -- Syntax styling belongs in on_highlights.
        -- Palette/background mutation belongs in on_colors.
      end

      return opts
    end,
  },
}
```

The important distinction:

```lua
opts.on_colors = function(colors)
  -- change base palette colors
end
```

Use this for things like:

- `bg`
- `bg_dark`
- `bg_float`
- `bg_sidebar`

And:

```lua
opts.on_highlights = function(highlights, colors)
  -- change final highlight groups
end
```

Use this for things like:

- Treesitter groups
- `WinSeparator`
- `NormalFloat`
- custom plugin highlights

Tiny rule:

```text
color ingredients go in on_colors
finished decorations go in on_highlights
```

## Toggle support

The plugin provides:

```vim
:MatugenMixEnable
:MatugenMixDisable
:MatugenMixToggle
```

The toggle is session-local by default.

That means after restarting Neovim, the plugin uses the configured value:

```lua
enabled = true
```

This is intentional. Persistent state can come later, when this tiny color helper
inevitably starts pretending to be infrastructure.

## Snacks toggle integration

If using `snacks.nvim`, add a toggle mapping.

Example:

```lua
return {
  {
    "folke/snacks.nvim",
    enabled = true,

    opts = {
      image = {
        enabled = true,
        doc = {
          inline = false,
          float = true,
          max_width = 40,
          max_height = 20,
        },
      },

      explorer = { trash = false },

      statuscolumn = {
        enabled = true,
      },
    },

    init = function()
      vim.api.nvim_create_autocmd("User", {
        pattern = "VeryLazy",
        callback = function()
          local Snacks = require("snacks")

          Snacks.toggle({
            name = "Matugen Mix",
            get = function()
              return require("matugen-mix").is_enabled()
            end,
            set = function(state)
              local matugen_mix = require("matugen-mix")

              if state then
                matugen_mix.enable()
              else
                matugen_mix.disable()
              end
            end,
          }):map("<leader>um")
        end,
      })
    end,
  },
}
```

Suggested keymap:

```text
<leader>um
```

Meaning:

```text
u = UI / toggles
m = Matugen Mix
```

Or, less officially:

```text
m = mood infection
```

## Configuration

Default-ish setup:

```lua
require("matugen-mix").setup({
  enabled = true,

  colors_module = "generated.matugen-colors",

  fallback_accent = "#7aa2f7",

  default_amount = 0.05,

  palette = {
    bg = 0.05,
    bg_dark = 0.04,
    bg_float = 0.06,
    bg_sidebar = 0.06,
  },
})
```

### `enabled`

Whether the mix is active.

```lua
enabled = true
```

When disabled, `apply_tokyonight()` does nothing and the colorscheme loads
normally.

### `colors_module`

The Lua module generated by `matugen`.

```lua
colors_module = "generated.matugen-colors"
```

This expects a file at:

```text
~/.config/nvim/lua/generated/matugen-colors.lua
```

Which can be required as:

```lua
require("generated.matugen-colors")
```

### `fallback_accent`

Used if the generated `matugen` file cannot be loaded.

```lua
fallback_accent = "#7aa2f7"
```

Because failing gracefully is better than exploding during startup like a tiny Lua
opera.

### `default_amount`

Default mix amount.

```lua
default_amount = 0.05
```

This means 5%.

Recommended range:

```text
0.03 - 0.08
```

Above that, the theme may stop looking gently adjusted and start looking like it
has joined a neon monastery.

### `palette`

Defines which colorscheme fields should be mixed and by how much.

```lua
palette = {
  bg = 0.05,
  bg_dark = 0.04,
  bg_float = 0.06,
  bg_sidebar = 0.06,
}
```

For TokyoNight, useful keys include:

```text
bg
bg_dark
bg_float
bg_sidebar
```

## Choosing an accent

Example:

```lua
matugen_mix.apply_tokyonight(colors, {
  accent = "primary",
})
```

Common options from the generated palette:

```text
primary
secondary
tertiary
background
surface
surface_variant
```

For the current `woman_reading_pinker.png` wallpaper, example values were:

```lua
primary = "#e6b6f1"
secondary = "#d5c0d7"
tertiary = "#f5b7b3"
```

Suggested behavior:

```text
primary   = stronger pink/purple influence
secondary = softer, safer influence
tertiary  = warmer pink/salmon influence
```

When in doubt, start with:

```lua
accent = "primary"
```

and small values:

```lua
bg = 0.05
```

If it becomes too pink:

```lua
accent = "secondary"
```

If it still looks dead:

```lua
bg = 0.07
```

If it looks like a nightclub for haunted TypeScript:

```lua
bg = 0.03
```

## Debugging

Check that the generated palette can be loaded:

```vim
:lua print(vim.inspect(require("generated.matugen-colors")))
```

Check the current primary color:

```vim
:lua print(require("matugen-mix").get_color("primary"))
```

Check a manual mix:

```vim
:lua print(require("matugen-mix").mix("#222436", "primary", 0.05))
```

Toggle on/off:

```vim
:MatugenMixToggle
```

Check whether it is enabled:

```vim
:lua print(require("matugen-mix").is_enabled())
```

## Recommended workflow

1. Change wallpaper.
2. Run `matugen`.
3. Start or reload Neovim.
4. Toggle Matugen Mix on/off.
5. Adjust mix amount if needed.
6. Stop before inventing a full theme engine.

The last step is important and will probably be ignored.

## Design principle

The plugin should stay boring.

Good boring.

The kind of boring where it does one thing, does not surprise you, and does not
turn into a config hydra.

Core idea:

```text
read generated colors
mix carefully
allow toggle
get out of the way
```
